## Sitemap 500 — root cause

Live `https://syncai.ca/sitemap.xml` is generated by Next’s **metadata** `app/sitemap.ts`, not a normal HTTP handler.

- Vercel serves it as `/sitemap.xml` with `Vary: rsc, next-router-state-tree, next-router-prefetch, next-router-segment-prefetch` and a sibling `/sitemap.xml.rsc` match.
- Simple `curl` often gets a multi-day `x-vercel-cache: HIT` and HTTP 200 (stale XML, no insight posts, no `lastmod`).
- Fetchers that send RSC/HTML Accept stacks, miss that CDN object, or go through GSC/WebFetch-style clients hit the metadata renderer and receive **HTTP 500**.
- `robots.txt` still advertises `Sitemap: https://syncai.ca/sitemap.xml`, so a 500 there blocks crawl.

**Fix:** delete `app/sitemap.ts`. Serve XML from `app/sitemap.xml/route.ts` (Node, `force-static`, always HTTP 200, `application/xml`). URL set is built in `lib/sitemap.ts`: required commercial routes + filesystem discovery of `app/**/page.tsx` (skips `permanentRedirect` / `noindexMetadata` / explicit exclude list) + every `app/insights/*/page.tsx` (and `lib/insights.ts` slugs). New marketing or Insights pages enter on the next build without a hand edit.

## Technical notes

- `lib/seo.ts` is the single source for titles, canonicals, and org/app schema.
- `lib/sitemap.ts` + `app/sitemap.xml/route.ts` generate `/sitemap.xml`. Do not reintroduce `app/sitemap.ts` (metadata route / RSC 500).
- `lib/insights.ts` is the article catalog used by the listing, sitemap fallback, and post metadata.
- Performance: no new client analytics, no extra fonts, no third-party SEO widgets. OG image is a static generated PNG from `next/og`.
